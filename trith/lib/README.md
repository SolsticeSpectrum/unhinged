# Trith standard library

The v1 standard library (HTTP, SMTP, WebSocket, SHA-256, AES, JSON), ported as C
modules that Trith programs bind with `⎔` (spec §14). Each module is one `X.c` and
its prototypes in `X.h`. Build a program that uses one with both flags:

```bash
./build/trithc main.trh --include trith/lib/json.h --link trith/lib/json.c -o main
./build/s2c   main.trh --include trith/lib/json.h --link trith/lib/json.c -o main
```

Both may be repeated to use several modules. `--include` puts the header into the
generated FFI glue, so the C compiler checks every binding against the real
prototype; `--link` compiles the C file into the program's LLVM module.

Conventions, chosen so that every function binds directly:

- Integers are `int64_t` (ℤ). Failure is −1, so a `◌ℤ` result fails exactly then.
- Strings come back as `const char *` in a buffer that the module reuses on its next
  call; the glue copies it at once. Failure is NULL, so a `◌ʃ` result fails then.
- Strings go in as NUL-terminated text: bind them `⟗ʃ` to lend the string, or `ʃ`
  to give it away (the glue frees it after the call).
- What arrives over the network is hearsay: declare those results `⸮` (§3.1), and
  declare `⸮ʃ` on parameters that may send hearsay back out.
- Each network module has an error getter that says, in words, why the last call
  failed.
- There is no TLS: `http://`, `ws://` and plain SMTP only.

The snippets below are in logical order (every line left to right); run
`trithc --plough` on a file before compiling it.

The tests in `tests/` use every function; read them as examples. They are written
as `X.trhx` (logical order with the s2 shorthands of `trith/s2/tools/trx.py`) and
the committed, ploughed `X.trh` is generated by `make lib-regen`. `make lib-test`
builds and runs each one with s1 and with s2 and compares its output with `X.out`
(the network tests fork, so one program is both server and client).

## crypto: SHA-256, HMAC, AES, random bytes

```
⎔ »652ahs_htirt« ⟨ʃ ⊸ ʃ⟩ ᛋ ⸫                 ⍝ trith_sha256(text): 64 hex digits
⎔ »652ahs_camh_htirt« ⟨ʃ ʃ ⊸ ʃ⟩ ᚺ ⸫           ⍝ trith_hmac_sha256(message, key): hex
⎔ »xeh_modnar_htirt« ⟨ℤ ⊸ ⸮◌ʃ⟩ ᚱ ⸫            ⍝ trith_random_hex(n): 2n hex digits
⎔ »tpyrcne_sea_htirt« ⟨ʃ ʃ ⊸ ʃ⟩ ᛖ ⸫           ⍝ trith_aes_encrypt(text, key)
⎔ »tpyrced_sea_htirt« ⟨ʃ ʃ ⊸ ◌ʃ⟩ ᛞ ⸫          ⍝ trith_aes_decrypt(hex, key)
```

AES is AES-256-CBC with PKCS#7 padding and a random IV; the key is the first 32
bytes of the key text, zero-padded. The ciphertext is hex(IV ‖ blocks). Decryption
fails on malformed hex or bad padding; there is no MAC, so add an HMAC of the
ciphertext if tampering matters.

## json: documents as text, read and changed by path

A path is keys and array indices joined by dots: `users.0.name`. The empty path is
the whole document.

| Function | Result |
|---|---|
| `trith_json_get(json, path)` | a string value decoded; any other value as compact JSON; NULL if missing |
| `trith_json_type(json, path)` | 0 missing, 1 null, 2 bool, 3 number, 4 string, 5 array, 6 object; −1 invalid JSON |
| `trith_json_len(json, path)` | elements of an array or members of an object; −1 otherwise |
| `trith_json_key(json, path, i)` | the i-th key of an object |
| `trith_json_at(json, path, i)` | the i-th element of an array, as compact JSON |
| `trith_json_bool(json, path)` | 1 true, 0 false, −1 not a bool |
| `trith_json_set(json, path, value)` | the document, compact, with the JSON value set at path (a missing key is added; index n of an n-element array appends) |
| `trith_json_quote(text)` | text as a JSON string literal |
| `trith_json_compact(json)` | the document without whitespace; NULL if invalid |

## http: HTTP/1.1 client and server

Client. `headers` holds extra `Name: value` lines separated by newlines (`""` for none).

| Function | Result |
|---|---|
| `trith_http_request(method, url, headers, body)` | the status, or −1 |
| `trith_http_response_body()` | the last response's body (chunked coding decoded) |
| `trith_http_response_header(name)` | one of its headers, or NULL |
| `trith_http_get(url)` | the body when the status is 2xx, else NULL |

Server. Trith has no callbacks, so a server is a loop: accept a request, read it,
respond.

| Function | Result |
|---|---|
| `trith_http_listen(port)` | the server's handle, or −1 |
| `trith_http_accept(server)` | the next request's handle, or −1 |
| `trith_http_req_method(req)`, `_path(req)`, `_body(req)` | parts of the request |
| `trith_http_req_header(req, name)` | one of its headers, or NULL |
| `trith_http_respond(req, status, content_type, body)` | 0 or −1; closes the request |
| `trith_http_close(server)` | stops listening |
| `trith_http_error()` | why the last call failed |

## ws: WebSocket (RFC 6455)

| Function | Result |
|---|---|
| `trith_ws_listen(port)` | the server's handle, or −1 |
| `trith_ws_accept(server)` | a connection after the opening handshake, or −1 |
| `trith_ws_connect(url)` | a connection to `ws://host[:port][/path]`, or −1 |
| `trith_ws_send(conn, text)` | 0 or −1 (frames from a client are masked) |
| `trith_ws_receive(conn)` | the next message; NULL when the peer closes (error `closed`) or the connection is lost |
| `trith_ws_close(conn)` | sends a close frame and closes (also closes a server) |
| `trith_ws_error()` | why the last call failed |

`trith_ws_receive` answers pings and joins fragmented messages. Messages are capped
at 16 MiB. It has been checked against Python's `websockets` in both directions.

## smtp: sending mail

| Function | Result |
|---|---|
| `trith_smtp_send(host, port, user, pass, from, to, subject, body)` | 0 or −1 |
| `trith_smtp_error()` | the failed step and the server's reply, e.g. `AUTH: 535 5.7.8 authentication failed` |

`to` is a comma-separated list; `from` and each recipient may be `Name <addr>`. An
empty `user` skips authentication; otherwise AUTH PLAIN is used. The body is plain
UTF-8 text: newlines become CRLF and leading dots are doubled.
